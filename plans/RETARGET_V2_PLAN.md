### 0.05 `형상°` 는 말단 구간이 지배한다 — 평균만 읽으면 오독한다

**실기 확인**: 조작자는 "겉으로는 잘 따라오는데 손끝마디가 굽어 있다"고 보고했고

**굽힘에서 net 의 앞 두 구간은 kp 보다 확실히 낫다**(17.3 vs 27.9, 23.6 vs 34.1).
말단만 46~68°로 튀어 평균을 망친다. 조작감과 어긋난 것은 net 이 아니라 **평균 지표**였다.

→ `tools/bench_hand_retarget.py` 에 **`말단°` 열을 추가**했다. 앞으로 `형상°` 평균만으로
판정하지 말 것. 말단이 크면 평균은 궤적과 무관하게 올라간다.

**원인은 손실에 손가락 내부 형상 항이 없다는 것.** `prox` 가 사슬 50% 지점이라 robotis 에서
사실상 사슬 3번째 점이고 `tip − prox` 가 곧 마지막 뼈 벡터다 — 정보는 keyvector 안에
있는데 요구하는 항이 없었다. `motion` 은 변화 방향만, `cover` 는 도달영역 소속만(말단이
굽은 자세도 도달 가능), `pinch` 는 지문끼리 거리만 본다. kp 는 이 항을 갖고 있고
(미터벡터 형상항) net 에만 없었다. TopoRetarget 의 `E_bone` 과 같은 것이다.

**기각된 대안 3건** (조작자가 물어본 것들):
- **affine** — 입력 keyvector 의 선형 보정이라 전역 정렬은 잡지만 **손실이 표현하지 않는
  제약을 만들어낼 수 없다.** 증상은 프레임 정렬이 아니라 관절공간 편향이다.
- **정규화** — `L_ref` 는 균일 스케일이라 손가락 내부 형상과 무관하다.
- **flat 데이터 보강만** — 이미 했다(q 공간 mix, 펼침 24%). 필요하지만 충분하지 않다.
  펼친 자세를 보여주는 것과 "말단을 사람처럼 펴라"고 요구하는 것은 다르다.

**Phase 2 구현 구멍도 같이 발견**: `align_loss` 를 `TIP = slice(0,3)` 으로 써서 지문
성분만 봤다 — 앵커를 켜도 말단은 안 잡혔을 것이다. 6D 전체로 고쳤다(`tip_only=True` 로
옛 동작 선택 가능).

→ `bone_loss(x, y)` = `tip − prox` 방향의 사람↔로봇 코사인 불일치. `--w-bone` 으로 켠다.

## 2. 새 방법론으로 폐기된 것

- **f_s 3안 비교(NNS / 학습IK / kp DLS)** — 통합 구조(F 가 q 직접 출력)라 해당 없음.
  측정해 둔 NNS 특성(사전샘플 20배에 오차 19.2→14.8mm, 1↔2위 이웃 q 점프가 밀도와
  무관하게 1.1rad 고정)은 **NNS 를 쓰지 않는 근거**로만 남긴다.
- **`sensor_proximal` 프레임을 prox 로 쓰는 것** — prox 는 **사슬 50% 중앙**으로 바뀐다.
  센서 실장 위치는 손마다 통일 작업이 반복돼 임베디먼트 확장에 약하다.
- **`v_tip→prox` keyvector** — `v_dorsum→{distal,prox}` 로 대체(선형종속 제외).
- **진행 중이던 tip/tip_prox 학습 런** — 키포인트 정의와 FK 가 둘 다 바뀌어 무효.
  (두 번 세션 경계에서 죽기도 했다. 재실행은 새 정의로.)

## 2.5 좌우 모델을 통합할지 — 결론: **통합을 목표로 설계, 도입은 미러 게이트 통과 후**

**통합이 가능한 근거.** 좌우 URDF 가 참 미러라면 팜프레임 로컬에서 왼손 keyvector 는
오른손 keyvector 의 z 성분 부호를 뒤집은 것과 **정확히** 같다(§0.1 의 비교식이 그것이다).
관절 한계도 좌우 동일하고 관절명은 접두사만 다르다. 따라서

```
q_robot = F( mirror_z(keyvector_left) )     # 같은 F, 같은 q
```

가 근사가 아니라 **엄밀한 대칭**이다. 같은 q 를 미러 기구에 넣으면 미러 동작이 나온다는 것을
§0.1 이 측정으로 확인했다(미러가 성립하는 관절에서 오차 0.00mm).

**통합해야 하는 이유 — 대칭성이 공짜로 보장된다.** 비지도 학습은 해가 유일하지 않아
시드마다 흔들린다(GeoRT 는 Ability Hand LMC 36.2±11.2 를 보고했다). 좌우를 **따로**
학습하면 두 손이 서로 다른 국소해에 앉아 **조작자가 왼손과 오른손에서 다른 감각**을 느낀다.
지금 겪는 흔들림과 결이 같은 문제이고, 통합은 이걸 구조적으로 없앤다. 부수 이득으로
학습 데이터가 2배(좌우 글러브 시퀀스를 미러로 합침), 체크포인트·학습시간은 절반이 된다.

**그런데 지금은 도입할 수 없다.** §0.1 대로 human 축 4/21, orca 3/17, robotis 8/20 이
미러가 아니고 중립형상도 human 4.77 / robotis 9.79mm 어긋난다. 미러가 깨진 상태에서
통합하면 한쪽 손의 오차를 다른 쪽에 강제로 떠넘긴다.

**따라서**: Phase 1·2 는 **왼손 side 별 모델**로 진행한다. `tools/check_mirror.py` 가
게이트이고, **손 하나가 축 0/N + 중립형상 2mm 이하가 되면 그 손만 통합으로 전환**한다.
orca 는 중립이 이미 0.03mm 이고 축 3개만 남아 먼저 열릴 가능성이 높다. robotis 는
중립 9.79mm + 축 8개라 더 걸린다 — 손별로 따로 판단한다.

**미러가 영구히 안 되는 손이 나오면** (설계상 좌우가 진짜 다른 경우) 그 손만 side 별
모델을 유지한다. 통합은 최적화이지 전제가 아니다.

5. 동봉 패키지 `dexhand_description` 은 여전히 구버전 관절명 → `WHATSLAB_MODELS_ROOT`
   를 반드시 건다. 패키지 릴리스 시 갱신 필요.

**Phase 1·2 는 왼손 단일 side 라 1~4 가 열리지 않아도 진행할 수 있다.** 게이트는 좌우
통합 모델의 전제다.

2. **Phase 2 `L_align`** — 대응을 고정하는 항은 이것뿐이다. 위 표가 앵커 기여를

**P0-3 답**: FK forward+backward 12,000 samples/s (배치 256 에서 학습스텝당 85ms)

### 4.2 두 수정

1. `w_coverage` **80 → 5**. §4.1 대로 `coverage 6.8e-3 × 80` 이 `motion 0.21` 을

2. `bone` 항 신설(§0.05). motion·coverage·pinch 중 **손가락 안쪽 형상을 보는 항이
   하나도 없어서** 손끝이 굽은 채 굳었다. `w_bone` 0/1/5/20 스윕에서 20 까지
   말단°가 계속 좋아졌고 포화하지 않았다 — 접촉지표를 악화시키지 않는 한 더 올릴 여지가 있다.

확정 설정: `--w-motion 1 --w-coverage 5 --w-bone 20 --random-mode mix --real-npz`
(실측 q 43%), 600 epoch, fp32, cuda.

### 4.4 Phase 2 합격선 (§4.3 이 기준선)

1. robotis 펴짐접촉 39mm → **10mm 이하** (kp 4.5)
2. robotis 핀치접촉 17.2mm → **10mm 이하** (kp 5.5)
3. 굽힘 이동량이 사람 쪽으로 이동 — robotis 검지 0.044 → **0.15 이상**, 소지 음수 해소

## 5. Phase 2 — AnyDexRT 4손실 + residual affine  **(L_align 기각 — §5.1, 앵커 없이 진행)**

`tools/train_hand_net.py --phase 2` 가 자동으로 켠다:

| 손실 | 구현 | Phase 1 대비 변경 |
|---|---|---|
| `L_P-Chamfer` | `coverage_loss(partial=True)` | 양방향 → **단방향**. 로봇 여분 영역 왜곡 회피 |
| `L_dist` | `distance_loss` | **신규**. 손가락쌍 거리 보존 |
| `L_motion` | `motion_loss_local` | 글로벌 → **로컬**. 두 섭동의 사잇각을 맞춘다 |
| `L_align` | `align_loss` + 앵커 | **신규**. 비지도 → 약지도 전환의 핵심 |
| affine | `AffineHandNet` / `ResidualAffine` | `A=0`,`b=0` 초기화라 항등에서 시작 |

**검증된 성질 두 개** (`tests/test_hand_net_losses.py`):
- `motion_loss_local` 은 6D 랜덤 회전에 대해 **정확히 0**, `motion_loss_global` 은 아니다.
  AnyDexRT 의 "로컬이 캘리브레이션에 강건" 메커니즘이 실제로 성립한다.
- `chamfer_partial` 은 로봇 여분 영역을 무시(0.0)하고 `chamfer_both` 는 39 이상 벌금.

**앵커 = 캘리 재활용.** 사람 쪽은 theta `flat(0)` ↔ `fist(theta_hi 의 _flex 만)`,
로봇 쪽은 관절 샘플에서 `dorsum→distal` 평균거리가 최대/최소인 구성을 flat/fist 로
잡는다 — **손 구조와 무관하게 유도되므로 손마다 라벨링이 필요 없다.** 보간은 양쪽 다
물리 파라미터(theta / q)에서 하고 그 다음 encode 한다. keyvector 공간에서 직접
보간하면 물리적으로 불가능한 중간 자세가 섞인다.

**ablation**: P5a affine 유/무(`--no-affine`), P5b 전처리 정규화 유/무,
단방향 Chamfer 유/무(`--partial-chamfer`), 로컬 motion 유/무(`--local-motion`).
전부 플래그로 분리돼 있어 한 번에 하나만 바꿀 수 있다.

**미해결 위험 — 외전 축 앵커가 없다.** flat/fist 는 굴곡-신전 축만 덮는다. 그런데
Phase 1 이 가장 크게 실패한 곳이 벌림축(GMC −37.9)이고 논문 앵커 두 유형 중 하나가
"측면 회전"이다. `ref/planing.md` VIII-1 **splay 캘리 자세 추가 가능 여부가 Phase 2
성패를 가른다.** 안 되면 벌림축은 `L_align` 이 못 잡고 `L_motion`/`L_dist` 에만 의존한다.

**판정**: LMC 우선, GMC 병기, `|dq|p95`. 기준선은 §0.

### 5.1 `L_align` 기각 — 앵커 목표 자체가 net 보다 나빴다

robotis 왼손 600 epoch x 4설정. `a_base` = Phase 1 확정 설정(`--real-repeat 1`).

| 설정 | 펴짐접촉 (pinch/flex/abd) | 핀치접촉 | flex 형상° | flex 말단° | flex GMC | flex LMC |
|---|---|---|---|---|---|---|
| kp | 4.5 / 5.0 / 7.1 | 5.5 | 34.0 | 39.9 | 95.3 | 63.4 |
| a_base | 29.5 / 30.9 / 33.2 | 13.8 | 23.3 | 28.2 | 89.5 | 72.5 |
| b_align (w=1) | 30.6 / 31.4 / 37.3 | 12.8 | 24.1 | 28.8 | 88.1 | 72.5 |
| c_align10 | **37.2 / 39.1 / 51.3** | 12.8 | 25.5 | 27.2 | **84.1** | 71.5 |
| d_align_dist | 30.9 / 31.4 / 47.3 | 12.4 | 25.4 | 26.5 | 85.7 | 74.5 |

**앵커를 세게 걸수록 목표 지표가 나빠진다.** 합격선 §4.4-1(펴짐접촉 10mm)에서 오히려
멀어지고 형상·GMC 까지 잃는다. `b_align` 의 align 손실은 600 epoch 동안 7.9e-2 에서
내려오지도 않았다.

**원인 — 앵커 목표가 오답이었다.** `robot_anchors` 는 **평균 펴짐지표 스칼라 하나의
argmax/argmin** 으로 로봇 flat/fist 를 고른다. 그 스칼라는 엄지가 손가락 대비 어디
있는지도, 손가락 형상도 제약하지 않는다. 유도된 앵커 자체를 재보면:

| robotis | 형상° | 말단° | 벌림mm | 접촉평균 |
|---|---|---|---|---|
| 유도 flat 앵커 | 43.3 | 36.6 | 0.7 | **57.3mm** |
| 유도 fist 앵커 | 65.4 | 97.5 | 42.9 | 50.3mm |
| (참고) kp flat 해 | 8.2 | 10.4 | 5.3 | **4.4mm** |
| (참고) kp fist 해 | 66.3 | 76.2 | 32.0 | 55.6mm |

net 은 이미 29.5mm 인데 **"정답"으로 준 것이 57.3mm 였다.** 오답 쪽으로 끌었으니
가중치를 올릴수록 나빠지는 게 당연하다. orca 도 같다(유도 flat 접촉 25.9mm).

**결정: 앵커를 쓰지 않는다.** 운영자 지시 — *"anchor 은 크게 안 써도 될 것 같은데 두
자세를 명시적으로 연결하는 건 하지 말자."* kp 해를 앵커로 쓰면 유도 앵커 문제는
사라지지만(kp flat 4.4mm) 그것도 자세 짝짓기이고, 무엇보다 **net 이 kp 를 모방하게 되어
net 의 존재 이유인 형상 우위를 잃는다**(kp fist 말단 76.2° vs net 28.2°). 구현해 봤다가
같은 이유로 되돌렸다. `--w-align` 플래그와 `align_loss` 는 남겨 두지만 기본 0 이고,
`--phase 2` 가 자동으로 켜던 것도 재검토 대상이다.

부수 소득: **kp 는 펴진 자세에서 거의 완벽하고(접촉 4.4mm / 형상 8.2°) 주먹에서
무너진다(55.6mm / 말단 76.2°).** net 은 정확히 반대다. 두 백엔드의 강점 구간이
상보적이라는 게 처음으로 수치로 나왔다.

### 5.2 앵커 대신 — `L_dist` (진행 중)

자세 짝짓기 없이 절대량을 제약하는 항. `distance_loss` 는 **손끝 쌍거리**
(`tip_i − tip_j`)를 사람↔로봇으로 맞춘다. 매 샘플에서 작동하고 대응을 못 박지 않는다.
실패 중인 지표(핀치접촉·펴짐접촉·벌림)가 **전부 손끝 쌍거리**라 정면으로 겨냥한다.
`run/p2d` 에서 `--w-dist` 1/5/20 을 다른 것 고정하고 스윕한다.

**주의할 실패 모드**: 양쪽 keyvector 는 각자의 `L_ref` 로만 정규화돼 있어
**L_ref 정규화 후에도 두 손이 기하적으로 닮았다고 가정**한다. 엄지는 안 닮았다
(펴진 자세 펴짐지표 사람 0.729 vs robotis 0.901). 안 닮은 축에서 등식을 강요하면
형상을 희생해 거리를 맞추므로, **dist 손실이 높은 값에서 정체하면서 형상이 나빠지면
그게 신호다** — 그때 필요한 것은 앵커가 아니라 학습되는 스케일(`ResidualAffine`)이다.

**`L_dist` 가 못 잡는 것**: 손가락별 펴짐량 `‖dorsum→tip‖` 자체는 쌍거리에 간접적으로만
들어간다. 굽힘 진폭 부족(§4.3)이 dist 로 안 잡히면 다음 후보는 이 크기를 직접 맞추는
항이고, 그것도 자세 짝짓기가 아니다.

### 5.3 손실 축소 — 7개 → 4개 (확정)

남긴 것: `motion_loss_local` + `coverage_loss` + `pinch_loss` + `position_loss`.
지운 것과 근거(전부 실측):

| 지운 항 | 근거 |
|---|---|
| `distance_loss` | 손끝 쌍거리를 줄이는 방법이 **굽히기와 모으기 둘**인데 후자가 싸다. `w_dist` 0→5→20 에서 검지 굽힘 이동량 **0.047 → 0.019 → 0.009**. 벌림 지표가 kp 를 넘어선 것과 굽힘이 죽은 것이 같은 현상의 양면이다 |
| `extension_loss` | `position_loss` 가 반경을 포함해 중복. `w=1` 에서 손실값 3e-3 로 사실상 꺼진 상태(`motion` 0.65 대비) |
| `flatness_loss` | 기울기 9.2e-9 |
| `bone_loss` | `position` 이 prox 를 포함하므로 중복 후보. 운영자 판단으로 제거 |
| `motion_loss_global` | 팜 프레임 방향(=GMC)만 맞춘다. net 은 GMC 92~99 로 이미 이기고 있었고 정작 미달인 LMC 는 겨냥하지 않았다 |

`motion` 은 항상 로컬이다. **부호·범위가 바뀐 것에 주의** — global 은 `−cos` 로 최소 −1
(실측 −0.65), local 은 제곱오차로 최소 **0**(실측 +0.49). `w_motion` 의 의미가 달라져
1 에서는 600 epoch 내내 0.35 에서 정체하고 5 에서 0.083 까지 내려간다.

### 5.4 `position` 을 끄면 붕괴한다 — 기각된 조합

운영자 지정 조합 `motion_local + L_P-Chamfer(단방향) + L_dist + L_smooth` 를
`position`·`pinch` 가중치 0 으로 돌린 결과, **완전 붕괴**했다. 펴짐~주먹 200자세를
넣어도 로봇 관절이 안 움직인다:

| 설정 | 출력 범위 최대 | 평균 |
|---|---|---|
| robotis, `w_smooth 0` | 1.73° | 0.84° |
| robotis, `w_smooth 10` | 1.06° | 0.49° |
| orca, `w_smooth 10` | **0.55°** | 0.23° |

**네 항 중 셋이 붕괴를 보상하거나 무력해진다:**

- **단방향 Chamfer 는 붕괴가 최저값이다.** 출력을 한 자세로 모으면 5.08e-5, random net
  8.34e-4 보다 **16배 낮다**. 역방향은 같은 붕괴를 2.71e-1 로 **5334배** 벌금 매긴다.
- **`L_smooth` 는 붕괴가 전역 최소(0)다.** "입력이 바뀌어도 출력이 안 바뀌게" 하는 항이라
  출력 고정이 완벽한 해다. 실제로 `w_smooth` 10 이 0 보다 출력범위를 더 좁혔다.
- **`motion_local` 은 `Δy≈0` 이면 무의미**해진다.
- `L_dist` 는 모든 쌍거리가 상수가 되어 한 값에 고정된다.

**손실값만 보면 붕괴가 안 보인다** — 그 런들도 `motion` 0.43 → 0.083, `dist` 0.30 → 0.28
로 잘 내려가는 것처럼 보였다. 출력 다양성을 따로 봐야 한다.

**이 구조에서 단방향 Chamfer 는 원리적으로 무정보다.** 출력이
`y = FK(joint_roms(tanh(net(x))))` 이므로 `y` 는 정의상 항상 도달 가능한 점이고,
`min_d` 는 유한 bank 의 이산화 오차만 잰다 — bank 를 2,000 → 100,000 으로 키우면
손실이 3.66e-3 → 2.55e-4 로 **14배 준다**(모델은 그대로). GeoRT 원본도
`fk_model(ik_model(point))` 구조라 순방향이 같이 공허하고, 그래서
`min_dist_a + min_dist_b` 양방향에 `w_chamfer=80` 을 준다. **정보가 있는 방향은
역방향(coverage)뿐이다.**

→ **`position` 을 빼려면 붕괴 방지 항이 따로 필요하다.** 양방향(또는 역방향 전용)
Chamfer 가 그 역할이고, 단방향으로 바꾸면서 `position` 까지 끄면 방지 장치가 0 이 된다.

### 5.5 `l_ref` 정의 — 되돌린 이력

세 번 바뀌었고 지금은 **팜 → 중지끝**(커밋 `786a054`)이다. 시도와 결과:

| 정의 | 결과 |
|---|---|
| dorsum → 중지끝 (원래) | 손실 스케일이 지표(`Fair.score`, 팜 기준)와 어긋난다 — robotis +5.7% / **orca −16.6%**. orca 펴짐접촉 17.6mm 의 거의 전부가 이 불일치였다 |
| **팜 → 중지끝** (현재) | 손실과 지표가 일치. orca 펴짐접촉 17.6 → 10.9mm, 핀치접촉 11.4 → **5.6mm**(kp 11.5 초과) |
| 손가락별 리치 정규화 | 중립 크기차가 0.048/0.023 → **0.002** 로 줄지만 **손가락 사이 상대 위치가 바뀌어 손 전체 형상이 왜곡**된다. `pinch_loss` 도 계산 불가가 된다(쌍거리가 공통 원점을 요구). **기각** |
| 모든 손가락 중 최대 도달거리 | 임의성은 없어지지만 값이 거의 같다(사람 196.1 → 197.1, robotis 243.5 → 244.3, orca 183.7 → 184.2mm) — 중립에서 중지가 이미 거의 최대 신전이라서다. 되돌림 |

**교훈**: 스케일은 한 개여야 형상이 보존된다. 손가락별 비율 차이(robotis 1.41배 /
orca 1.45배)는 진짜 형태 차이이고 **형상을 지키면서는 어떤 방법으로도 없앨 수 없다** —
affine 이 배우든 `L_f` 로 나누든 같다. affine 에 기대했던 역할이 이것이었으나 원리적으로
불가능하다(게다가 affine 은 손실 **입력** 쪽이라 목표를 못 바꾼다).

3.3~4.0mm), `Fair.score` 의 스케일 불일치(orca 19.9mm 불리), `형상°` 평균의 말단 지배.
운영자 보고("손 모양은 다 잘 추종한다", "`R2_orca` 괜찮다")와 어긋난 지표가 반복해서

| 높음 | **이동량**(펴짐→주먹), **출력범위(deg)** | 로봇이 실제로 굽는지·움직이는지. 프레임·스케일 무관. **붕괴 감지의 유일한 수단** |

### 5.8 상수 스윕과 적정 epoch (확정)

기준선 `c2c7967`(motion 1 / coverage 5 / bone 20 / pinch 1 / pos 20). robotis 왼손
`flex`, epoch 400, 한 번에 하나만 바꿈:

| 설정 | 형상° | 말단° | 펴짐접촉 | GMC | LMC | \|dq\|p95 |
|---|---|---|---|---|---|---|
| 기준선 | 27.4 | 24.3 | 13.5 | 88.8 | 86.2 | 0.346 |
| **`w_motion 5`** | **25.3** | **23.1** | **13.1** | **91.2** | **88.4** | **0.342** |
| `w_bone 4` | 25.8 | **21.9** | **10.6** | 88.7 | 85.7 | 0.429 |
| `w_bone 100` | 28.2 | 26.2 | 18.0 | 87.9 | 86.1 | 0.349 |
| `w_coverage 1` | 28.2 | 23.2 | 14.6 | 88.5 | 86.2 | 0.405 |
| `w_coverage 25` | 25.2 | 25.0 | 16.7 | 88.2 | 83.7 | 0.335 |
| `w_pos 4` | 26.6 | 27.7 | 25.1 | 90.4 | 86.0 | **0.279** |
| `w_pos 100` | 27.4 | 23.0 | **9.2** | 86.7 | 82.5 | 0.587 |

1. **`w_motion` 1 → 5 가 유일하게 전 항목을 개선한다** (벌림만 8.7 → 10.3).
2. **`w_bone` 20 → 4 가 말단·펴짐접촉을 개선한다.** `position` 이 6D 전체를 보고
   `bone` 이 그 6D 의 방향을 보므로 정보가 겹친다 — 겹친 쪽을 줄이는 것이 낫다.
   대가는 `|dq|` 0.346 → 0.429 다.
3. **`w_pos` 는 "손이 안 펴짐 ↔ 덜컹거림" 손잡이다.** 100 → 펴짐접촉 9.2 / `|dq|`
   0.587, 4 → 25.1 / 0.279. 운영자 불만 두 개가 같은 항의 양면이다.
4. `coverage` 는 25 로 올리면 LMC 를 깎는다(83.7). 5 를 유지한다. 주의: 손가락별로
   합산되므로 5손가락에서 실효 25 이고 4손가락 손에서는 20 이 된다.

**적정 epoch 는 400 이다.** 검증 손실이 300~400 에서 정체하고 600 까지 반등이 없다
(300→600 이득 1.4~2.3%). 벤치도 같은 지점에서 평평하다 — LMC 가 epoch
100/200/300/**400**/500/600/1000 에서 82.8/84.5/85.9/**86.2**/86.4/86.3/85.7 이고
말단°는 100 부터 평평하다. 600 을 넘기면 이득 없이 `|dq|` 와 LMC 가 약간 나빠지고,
출력 포화가 깊어져 관절이 죽는 부작용이 있다(dg5f 소지 뿌리 300epoch 6.5°/포화87%
→ 1000epoch 0.4°/포화100%). 손실만 보면 안 보이는 비용이다.

**검증 손실은 런 내부 epoch 선택에만 쓴다.** 가중치가 다른 런은 총손실 정의가 달라
비교할 수 없다(`--w-pos 4` 런이 정의상 작다). 가중치 순위는 벤치로만 정한다.

### 5.9 LMC 는 게이지 인공물이었다 (지표 수정)

옛 LMC 는 로컬 프레임을 `z` = 마지막 뼈(내재적), `x` = `z × ŷ` 로 세워 **롤 기준을
팜 y 축에 못박았다.** 로봇 손가락이 중립에서 벌어져 있으면 `x`·`y` 가 같이 돌아
맞는 움직임인데 점수가 깎인다:

| | 옛 LMC | 롤정렬 | 게이지무관 | 롤차 |
|---|---|---|---|---|
| robotis abd | 80.3 | 99.1 | 99.3 | 24.9° |
| orca abd | **41.0** | **92.1** | 99.8 | 50.0° |
| dg5f abd | 44.2 | 78.9 | 94.1 | 51.9° |

**`orca 벌림 LMC 41.0` 은 리타게팅 실패가 아니라 고정 롤차 50° 였다.** 지금은 뼈축을
최소회전으로 맞춘 뒤 방향을 비교한다(프레임 무관량). 고친 뒤 net 이 LMC 네 경우
모두 kp 를 이긴다(85.7/99.1/82.2/92.2 vs 78.4/99.2/77.1/88.3).

### 5.10 방위는 어떤 항도 잡지 않고 있었다

keyvector 는 tip·prox **위치** 둘뿐이라 뼈축 주변 롤을 잡는 항이 없다. 말단 센서
프레임의 방위를 재면(중립 규약차 `D = A_r A_hᵀ` 를 상수로 뺀 뒤) robotis abd 97.7 /
orca abd **39.3** / dg5f abd 56.5 다. orca 벌림은 위치로는 정상(게이지무관 99.8)인데
방위로는 39.3 이다. `orientation_loss` 를 넣었다 — `A_r` 이 `D A_h` 가 되게 하는
Frobenius 거리다(log3 의 특이점 회피). 학습 중 섭동은 keyvector 공간의 난수라
대응하는 사람 회전이 없으므로 상대회전(SMC) 대신 절대 방위로 건다.

부수 발견: **dg5f 의 `{side}_sensor_{finger}_distal` 이 179° 뒤집혀 있다**(robotis
6~10°, orca 26~40°). URDF 좌표계 문제라 dg5f 는 실험 대상에서 제외했다.

### 5.11 ResidualAffine 은 표현력이 0 이었다 (제거)

`x + W_f x + b_f` 는 활성화 없는 손가락별 선형층이고 바로 뒤가 `Linear(6,128)` 이다.
비선형이 없는 두 선형사상은 합쳐지므로 단일 `Linear` 로 정확히 재구성된다(최대차
8.9e-16). 손가락별 캘리브레이션 역할을 기대했지만 선형층 앞에서는 구조상 불가능하다.
제거했고, 기존 체크포인트는 `affine.*` 키 때문에 더 못 읽는다 — 필요하면 `390ce96`
으로 체크아웃한다.

같은 검토에서: **BatchNorm 은 쓰지 않는다.** 유한차분 대 참야코비안 cos 은 세 설정
모두 1.0000 이라 손실 오염은 없지만(처음 주장은 틀렸다), 배치 조성 민감도가
none/layer 1.1e-16 대 batch **0.378** 이다 — 출력이 `tanh` 라 범위 `[-1,1]` 이므로
전체의 19% 다. eval 에서 running stats 로 바뀌어 학습한 함수와 추론 함수가 다르고
추론은 batch=1 이다. 정규화가 필요하면 LayerNorm 을 쓴다.

### 5.7 남은 것

`c0476ff` 4항 조합 자체의 학습 런이 없다. 기존 체크포인트(`run/p2rs`·`p2ps`)는
`bone`·`motion_global` 시절이라 이 조합의 증거가 아니다 — `l_ref` 만 일치하므로
**추론은 정상이지만 4항 조합의 판정에는 쓸 수 없다.** 운영자 판단으로 학습을 중단한
상태이고, 재개하면 `w_motion` 5 근처 / `w_pos` 스윕(팜 `l_ref` 기준 10~20)에서 시작한다.

## 6. Phase 3 — 셀슈바 백본 + 다중 임베디먼트  **(Phase 1·2 완료 후)**

`ref/planing.md` IV Phase 3 를 기준으로 하되, 목적함수는 아래로 확정한다.

```
L_backbone = λ1·L_smooth + λ2·L_contrastive(clean/noisy) + λ3·L_feasibility(joint_roms)
```

| 항 | 식 | 무엇을 위한 것인가 |
|---|---|---|
| `L_smooth` | `E_x[ ‖f_θ(x+δ) − f_θ(x)‖² / ‖δ‖² ]`, 작은 δ (Lipschitz 근사) | **few-shot 정당화.** 앵커 하나가 주변 이웃까지 대신 끌어주게 latent 를 부드럽게 정렬한다 |
| `L_contrastive` | `InfoNCE(z_clean, z_noisy_same_pose)` vs negative(다른 pose) | **VLA 정당화.** 노이즈 성분이 latent 에 새지 않게 — latent 는 순수 기구학적 자세만 담는다 |
| `L_feasibility` | 아래 참조 | 도달 불가 영역으로의 매핑 억제 |

**빠지는 것**: masked reconstruction, 뼈길이 불변항. 두 정당화 어느 쪽도 직접 요구하지
않는다. **남는 것**: temporal smoothness (VLA 도 시퀀스 예측이라 공통 요구).

**두 정당화는 서로 긴장 관계다.** 글러브 센서 노이즈(드롭아웃·EM 간섭)에 강하게 적응시키면,
VLA 가 나중에 내는 (노이즈 없는) 키포인트 예측과 latent 사이에 분포 괴리가 생긴다.
즉 강건성을 위한 노이즈 aug 가 VLA 연결 시 독이 될 수 있다. `L_contrastive` 는 이걸
"노이즈 강건성은 유지하되 latent 표현은 노이즈 무관"으로 분리하는 장치다.

**중복 위험 3건 — 가중치를 낮게 시작한다.**
1. `L_metric`(latent 위의 pairwise 거리보존)은 Phase 2 의 `L_dist`(keyvector 위)와 겹친다.
   keyvector 가 이미 6D 상대구조라 latent 에 또 얹는 건 중복 정규화일 수 있다 → **기본 제외**,
   ablation (d) 에서만 켠다.
2. `L_smooth` 는 **GeoRT flatness 와 겹친다.** flatness 는 `(f(x+δ)+f(x−δ)−2f(x))²` 로
   2차차분이고 둘 다 이미 구현돼 있다. 차이는 출력단(정확 FK 통과) vs latent 단이다.
   출력단 항이 이미 있는 상태에서 추가 이득이 있는지부터 잰다.
3. Phase 1 실측에서 **flatness 가 1e-10 수준**으로 사실상 0 이었다 — 이 계열 항이
   현재 스케일에서 학습에 기여하지 않는다는 신호다. `L_smooth` 도 같은 함정에 빠질 수 있으니
   δ 크기와 가중치를 먼저 검증한다.

**`L_feasibility` 는 재해석이 필요하다.** 출력이 `tanh → joint_roms` 선형 매핑이라
q 는 **구조적으로 항상 범위 안**이다 → q 에 대한 feasibility 페널티는 공허하다.
의미 있는 형태는 **tanh 포화 억제**다: `E[ relu(|pre_tanh| − c)² ]`. 포화하면 그래디언트가
죽고 관절이 한계에 달라붙는다(팔 IK 에서 joint5 가 가동범위 하한에 45% 프레임 붙어 있던
것과 같은 실패). 이걸 `L_feasibility` 로 쓴다.

**필수 ablation** (이게 없으면 정당화가 아니라 가설이다). **같은 gradient step 수로 맞추고**
few-shot 앵커 학습까지 끝낸 뒤 LMC 를 비교한다:

| | backbone pretext | 확인하는 것 |
|---|---|---|
| (a) | 없음 (Phase 2 손실만, backbone 포함 end-to-end) | 기준선 |
| (b) | `+ L_smooth` | 매끄러움이 few-shot 효율을 올리는가 |
| (c) | `+ L_smooth + L_contrastive` | 노이즈 불변이 추가 이득이 있는가 |
| (d) | `+ 전부 + L_metric` | 중복 정규화인지 확인 |

**(b) 가 (a) 를 못 이기면 backbone pretext 는 기각하고 Phase 2 상태를 최종으로 둔다.**

**두 번째 필수 실험**: **앵커 개수(5/10/20/50) 대비 LMC 곡선을 백본 유/무로 비교.**
이게 없으면 "백본 없이 손마다 5~10분 학습하면 되는데 왜?"에 답할 수 없다. 백본의 가치는
품질이 아니라 **로봇이 몇 대든 공유된다**는 것이므로, 곡선의 기울기가 근거가 된다.

## 7. 규칙

- 한 번에 하나만 바꾸고 ablation. 측정 전에 단정하지 않는다.
- 남의 논문 수치는 우리 하네스로 재현 전까지 설계 근거로 쓰지 않는다
  (AnyDexRT 의 LMC 우위는 저자 정의·자체 재구현 비교이고 핵심 ablation 이 한 손뿐이다).
- 기각도 근거와 함께 남긴다. 목표 기반 지표로 백엔드를 비교하지 말 것(과거 두 번 틀렸다).
