### 0.1 좌우 미러 실측 (통합 판단의 전제)

`tools/check_mirror.py`. 같은 q 를 좌우에 넣고 팜프레임 로컬 사슬 좌표를 `(x, y, -z)` 로
비교한다. **두 실패 모드를 분리해서 잰다** — 섞으면 중립 오프셋이 모든 관절을 오염시켜
전 관절 실패로 보인다(실제로 처음에 robotis 를 20/20 으로 오판했다).

| | 중립형상 | 축 미러오차>2mm | 최악 | 어긋난 관절 |
|---|---|---|---|---|
| human | 4.77mm | **4/21** | 81.9mm | `{index,middle,ring,pinky}_mcp_abd` |
| orca | 0.03mm | **3/17** | 11.2mm | `{I,M,P}-AP_*_to_*Carpals*` (외전축) |
| robotis | 9.79mm | **8/20** | 95.9mm | `finger_?_joint{1,2,5,9,13,17}` 계열 |

- **중립형상** = q=0 에서의 기하 비대칭. 링크 원점·길이가 좌우로 다른 것.
  orca 는 사실상 완전(0.03mm), human 은 4.77mm(엄지 말단 뼈가 1mm 다르다),
  robotis 는 9.79mm 로 전 손가락 균일 → 체계적 오프셋이다.
- **축 미러오차** = 중립을 뺀 변위의 미러 불일치. 회전축 부호/방향 문제만 남는다.
  human 은 정확히 `*_mcp_abd` 4개 — `axis="0 0 1"` 이 좌우 동일한데 축은 의사벡터라
  미러 시 `a' = -M a` 로 부호가 바뀌어야 한다. 오른손 4개만 반전하면 5·15·25° 전부 0.00mm.

이전 세션 기록 두 건은 **틀렸다**: "robotis 는 완전한 미러(0.0mm) / orca 는 35~45mm
어긋남"은 지문 위치만 옛 URDF 로 잰 값, "robotis 20/20"은 중립 오프셋 미분리. 위 표가 정본.

**이전 세션의 형상 43.3° 표도 폐기.** 사람 URDF 관절명이 구버전이라 프로파일과 13/21 이
어긋난 상태의 측정이다. Phase 1 의 "43.3° → 20°" 목표는 §0 새 기준선으로 다시 잡는다.

## 2. 새 방법론으로 폐기된 것

- **f_s 3안 비교(NNS / 학습IK / kp DLS)** — 통합 구조(F 가 q 직접 출력)라 해당 없음.
  측정해 둔 NNS 특성(사전샘플 20배에 오차 19.2→14.8mm, 1↔2위 이웃 q 점프가 밀도와
  무관하게 1.1rad 고정)은 **NNS 를 쓰지 않는 근거**로만 남긴다.
- **`sensor_proximal` 프레임을 prox 로 쓰는 것** — prox 는 **사슬 50% 중앙**으로 바뀐다.
  센서 실장 위치는 손마다 통일 작업이 반복돼 임베디먼트 확장에 약하다.
- **`v_tip→prox` keyvector** — `v_dorsum→{distal,prox}` 로 대체(선형종속 제외).
- **진행 중이던 tip/tip_prox 학습 런** — 키포인트 정의와 FK 가 둘 다 바뀌어 무효.
  (두 번 세션 경계에서 죽기도 했다. 재실행은 새 정의로.)

## 2.5 좌우 모델을 통합할지 — 결론: **통합을 목표로 설계, 도입은 미러 게이트 통과 후**

**통합이 가능한 근거.** 좌우 URDF 가 참 미러라면 팜프레임 로컬에서 왼손 keyvector 는
오른손 keyvector 의 z 성분 부호를 뒤집은 것과 **정확히** 같다(§0.1 의 비교식이 그것이다).
관절 한계도 좌우 동일하고 관절명은 접두사만 다르다. 따라서

```
q_robot = F( mirror_z(keyvector_left) )     # 같은 F, 같은 q
```

가 근사가 아니라 **엄밀한 대칭**이다. 같은 q 를 미러 기구에 넣으면 미러 동작이 나온다는 것을
§0.1 이 측정으로 확인했다(미러가 성립하는 관절에서 오차 0.00mm).

**통합해야 하는 이유 — 대칭성이 공짜로 보장된다.** 비지도 학습은 해가 유일하지 않아
시드마다 흔들린다(GeoRT 는 Ability Hand LMC 36.2±11.2 를 보고했다). 좌우를 **따로**
학습하면 두 손이 서로 다른 국소해에 앉아 **조작자가 왼손과 오른손에서 다른 감각**을 느낀다.
지금 겪는 흔들림과 결이 같은 문제이고, 통합은 이걸 구조적으로 없앤다. 부수 이득으로
학습 데이터가 2배(좌우 글러브 시퀀스를 미러로 합침), 체크포인트·학습시간은 절반이 된다.

**그런데 지금은 도입할 수 없다.** §0.1 대로 human 축 4/21, orca 3/17, robotis 8/20 이
미러가 아니고 중립형상도 human 4.77 / robotis 9.79mm 어긋난다. 미러가 깨진 상태에서
통합하면 한쪽 손의 오차를 다른 쪽에 강제로 떠넘긴다.

**따라서**: Phase 1·2 는 **왼손 side 별 모델**로 진행한다. `tools/check_mirror.py` 가
게이트이고, **손 하나가 축 0/N + 중립형상 2mm 이하가 되면 그 손만 통합으로 전환**한다.
orca 는 중립이 이미 0.03mm 이고 축 3개만 남아 먼저 열릴 가능성이 높다. robotis 는
중립 9.79mm + 축 8개라 더 걸린다 — 손별로 따로 판단한다.

**미러가 영구히 안 되는 손이 나오면** (설계상 좌우가 진짜 다른 경우) 그 손만 side 별
모델을 유지한다. 통합은 최적화이지 전제가 아니다.

(이 런의 `ms` 열은 학습이 CPU 를 같이 써서 무효. 학습 후 재측정한다.)

**벌림축 GMC 가 −37.9 다 — 사람이 벌리면 로봇이 반대로 간다.** 튜닝 문제가 아니라
구조적 실패다.

**원인.** GeoRT 5원칙에는 **사람 자세를 특정 로봇 자세에 묶는 항이 없다.**
motion(방향 일치)·coverage(도달영역 덮기)·flatness·pinch 뿐이고, 어느 것도 대응 관계를
고정하지 않는다. 비지도 해의 비유일성이 그대로 나온다 — `ref/planing.md` X-5 의 예측과
같다. 게다가 **motion 이 −0.21 에서 30 epoch 정체**했다(목표 −1.0):
`coverage 6.8e-3 × 80 = 0.54` vs `motion 0.21` 로 coverage 가 여전히 지배한다.
`w_coverage=80` 은 GeoRT 가 축별 [−1,1] 정규화에 맞춰 잡은 값인데 우리는 `L_ref`
하나로만 정규화하므로 스케일이 다르다.

**GMC 가 음수인 구간에서는 격차(LMC−GMC)를 읽지 말 것.** net 벌림축의 +51.7 은
GMC 가 −37.9 라서 나온 값이고 좋은 신호가 아니다. 전역 정렬이 양수 영역에 들어온
뒤에 격차를 본다.

**다음 두 단계** (순서 고정):
1. **가중치 스윕** — `--w-motion` 을 올리고 `--w-coverage` 를 내려 motion 이 실제로
   수렴하는지. 한 번에 하나만 바꾼다.
2. **Phase 2 `L_align`** — 대응을 고정하는 항은 이것뿐이다. 위 표가 앵커 기여를
   측정할 비교 기준선이고, 계획서가 Phase 1 을 비지도로 두라고 한 이유가 이것이다.

**P0-3 답**: FK forward+backward 12,000 samples/s (배치 256 에서 학습스텝당 85ms)
→ 200 epoch 약 7분. `pytorch_kinematics` 병행 불필요. 전부 CPU 라 GPU 부하가 없어
하드 리셋 위험도 없다. net 추론은 0.21ms (kp 1.89ms) — FK 없는 forward 1회.

| 손실 | 구현 | Phase 1 대비 변경 |
|---|---|---|
| `L_P-Chamfer` | `coverage_loss(partial=True)` | 양방향 → **단방향**. 로봇 여분 영역 왜곡 회피 |
| `L_dist` | `distance_loss` | **신규**. 손가락쌍 거리 보존 |
| `L_motion` | `motion_loss_local` | 글로벌 → **로컬**. 두 섭동의 사잇각을 맞춘다 |
| `L_align` | `align_loss` + 앵커 | **신규**. 비지도 → 약지도 전환의 핵심 |
| affine | `AffineHandNet` / `ResidualAffine` | `A=0`,`b=0` 초기화라 항등에서 시작 |

**검증된 성질 두 개** (`tests/test_hand_net_losses.py`):
- `motion_loss_local` 은 6D 랜덤 회전에 대해 **정확히 0**, `motion_loss_global` 은 아니다.
  AnyDexRT 의 "로컬이 캘리브레이션에 강건" 메커니즘이 실제로 성립한다.
- `chamfer_partial` 은 로봇 여분 영역을 무시(0.0)하고 `chamfer_both` 는 39 이상 벌금.

**앵커 = 캘리 재활용.** 사람 쪽은 theta `flat(0)` ↔ `fist(theta_hi 의 _flex 만)`,
로봇 쪽은 관절 샘플에서 `dorsum→distal` 평균거리가 최대/최소인 구성을 flat/fist 로
잡는다 — **손 구조와 무관하게 유도되므로 손마다 라벨링이 필요 없다.** 보간은 양쪽 다
물리 파라미터(theta / q)에서 하고 그 다음 encode 한다. keyvector 공간에서 직접
보간하면 물리적으로 불가능한 중간 자세가 섞인다.

**ablation**: P5a affine 유/무(`--no-affine`), P5b 전처리 정규화 유/무,
단방향 Chamfer 유/무(`--partial-chamfer`), 로컬 motion 유/무(`--local-motion`).
전부 플래그로 분리돼 있어 한 번에 하나만 바꿀 수 있다.

**미해결 위험 — 외전 축 앵커가 없다.** flat/fist 는 굴곡-신전 축만 덮는다. 그런데
Phase 1 이 가장 크게 실패한 곳이 벌림축(GMC −37.9)이고 논문 앵커 두 유형 중 하나가
"측면 회전"이다. `ref/planing.md` VIII-1 **splay 캘리 자세 추가 가능 여부가 Phase 2
성패를 가른다.** 안 되면 벌림축은 `L_align` 이 못 잡고 `L_motion`/`L_dist` 에만 의존한다.

**판정**: LMC 우선, GMC 병기, `|dq|p95`. 기준선은 §0.

## 6. Phase 3 — 셀슈바 백본 + 다중 임베디먼트

`ref/planing.md` IV Phase 3 그대로. **필수 실험은 앵커 개수(5/10/20/50) 대비 LMC 곡선을
백본 유/무로 비교**하는 것 하나다 — 이게 없으면 "백본 없이 손마다 5~10분 학습하면
되는데 왜?"에 답할 수 없다.

## 7. 규칙

- 한 번에 하나만 바꾸고 ablation. 측정 전에 단정하지 않는다.
- 남의 논문 수치는 우리 하네스로 재현 전까지 설계 근거로 쓰지 않는다
  (AnyDexRT 의 LMC 우위는 저자 정의·자체 재구현 비교이고 핵심 ablation 이 한 손뿐이다).
- 기각도 근거와 함께 남긴다. 목표 기반 지표로 백엔드를 비교하지 말 것(과거 두 번 틀렸다).
