# 글러브 기반 크로스-임베디먼트 리타게팅 — 최종 방법론

작성 원칙
- **한 번에 하나씩 바꾸고 ablation.** 측정 전에 단정하지 않는다.
- 남의 논문 수치는 우리 하네스로 재현하기 전까지 설계 근거로 쓰지 않는다.
- 확정 / 조건부 / 미결정을 구분해 기록한다.

# I. 프로젝트 포지셔닝

## 1. 한 줄 주장

> 글러브 기반 사람 데이터 수집의 병목은 **리타게팅 품질**이었고, 그래서 이 분야는
> 로봇별 동형(isomorphic) 장치로 이동했다. 리타게팅을 충분히 좋게 만들면
> **수집 장치 하나로 N개 로봇을 커버**할 수 있다.

## 2. 관련 연구 지형

### 데이터 수집 패러다임 — "perioperation"
DEXOP가 명명. 원격 조종이 아니라 **사람이 착용하고 자기 조작을 하면서** 비전·고유감각·
촉각·액션을 기록하는 방식. 텔레옵 대비 수집 시간당 정책 성능이 높다고 보고.

| 시스템 | 방식 | 한계 |
|---|---|---|
| **DexCap** (2024) | EMF 모캡 글러브 + SLAM. 지문 IK로 LEAP 16-DoF 리타게팅 | 리타게팅 의존, EMF 간섭, 단일 로봇 |
| **DexUMI / RealDexUMI** | 로봇 손과 동형인 착용 장치 → 리타게팅 제거 | **특정 로봇에 하드웨어가 묶임** |
| **DEXOP** (2025) | 사람 손과 수동 로봇 손을 분리·공동설계해 전이성 극대화 | 동일. 로봇별 장치 재제작 |

**분야의 글러브 비판**: DexUMI — "DexCap은 모캡 글러브로 접촉 중 데이터를 수집하지만
여전히 리타게팅 방법과 실세계 로봇 데이터에 의존한다." DEXOP — "한계가 있는 촉각 글러브를
쓰는 대신, 사람 손과 수동 로봇 손을 분리해 기구학 사슬·형상·센서를 일치시킨다."

→ **이 비판의 대상(리타게팅)이 정확히 우리가 만드는 것.** 동형 장치의 대가는
임베디먼트 종속이고, 글러브는 임베디먼트 무관하다는 것이 우리 자리.

### 리타게팅 계보
| | 코드 | 우리와의 관계 |
|---|---|---|
| DexPilot / AnyTeleop | 공개(dex-retargeting) | 매 프레임 최적화. 실시간 부담으로 제외 |
| **GeoRT** (2025) | 공개(facebookresearch) | **Phase 1 기준.** 네트워크가 q 직접 출력 + frozen neural FK |
| **AnyDexRT** (2026.07) | **미공개** | **Phase 2 기준.** 4손실 + few-shot anchor |
| TopoRetarget | 미공개 | **전용 불가** — 물체 메쉬 필수(21키포인트+물체표면 50샘플 Delaunay→라플라시안). 물체 없는 텔레옵에 못 씀 |
| keyvector (DexPilot 용어) | — | 표현만 부분 채택. 스위칭 keyvector는 측정 기각됨 |

### 크로스-임베디먼트 액션공간 (Phase 3 경쟁군)
| | 공유 공간 | 학습 데이터 | 전이 |
|---|---|---|---|
| XL-VLA (2026.03) | 학습된 latent | 멀티핸드 텔레옵 2M 페어 | zero-shot 주장 |
| UHAS (2026.07) | 표준 구(sphere) 변형 + Cascade IK | RL | zero-shot 주장 |
| CrossDex | eigengrasp | — | — |
| **우리** | **사람 keypoint** | **사람 착용 데이터** | few-shot anchor |

**차별점**: 공유 공간이 학습 latent나 추상 기하가 아니라 **물리적으로 접지된 사람 keypoint**.
→ 로봇 텔레옵 데이터 없이 사람 데이터만으로 확장 가능.
**불리점**: 경쟁군은 zero-shot을 주장하는데 우리는 few-shot 앵커가 필요.
→ "앵커를 쓰는 대신 품질이 확실히 낫다"를 보여야 함.

## 3. 우리 하드웨어의 실제 차별점

| | DexCap | 우리 |
|---|---|---|
| 센싱 | EMF 지문 위치 | **IMU 각도** |
| EM 간섭 | 취약 (AnyDexRT가 지적한 핀치 측정 실패 원인) | 없음 |
| 사용자 편차 | 손 크기별로 절대위치 상이 | **글러브 기구학 고정 + flat/fist/pinch 캘리** |
| 촉각 | 없음 | **있음** |
| 로봇 지원 | LEAP 1종, 지문 IK | **다중 (Phase 3 목표)** |

**주의**: "CV 가림에 강하다"는 우리 차별점이 아니다. DexCap이 EMF를 택한 이유가
이미 그것이며, 논문에 명시돼 있다.

**하드웨어 조건의 이점과 함정**
- 이점: 손 크기 변수 소거 → 입력 분포가 관절각 하나로 결정. 로봇도 고정 기구학이라
  양측이 "고정 기구학 + 가변 관절각"이라는 대칭 구조.
- 함정: 글러브가 사용자 손 크기를 무시 → 실제 접촉 순간과 FK상 접촉 순간이 어긋남.
  → **캘리브레이션이 흡수.** 따라서 캘리 이후 데이터는 사용자 무관해지고
  anchor를 사용자별로 재수집할 필요가 없다.

# II. 확정 구조

```
① 글러브 q_human (22 DoF)
      ↓ 사람 URDF FK (pinocchio, 그래디언트 불필요)
② 사람 keypoint : dorsum(원점) / {finger}_prox(사슬 중앙) / {finger}_distal(손끝)
      ↓ 전처리 (§III)
③ 사람 keyvector : 손가락당 6D
      ↓
      ★ F : 학습 네트워크 — 유일한 학습 대상
      ↓
⑤ q_robot (17 DoF, tanh → joint_roms 매핑)  ──→ 실행 출력
      ↓ pinocchio FK (야코비안으로 미분 통과. 학습 시에만)
⑥ 로봇 keypoint → 로봇 keyvector
      ↓
⑦ 손실(keypoint 공간) → J^T 로 F에 역전파
```

- GeoRT와 같은 구조(q 직접 출력)이되 **frozen neural FK 대신 pinocchio 정확 FK**.
  AnyDexRT가 지적한 GeoRT 한계 3가지 중 첫 번째(신경망 FK 근사 오차)를 구조적으로 회피.
- 미분 연결: `∂L/∂q = (∂L/∂x)^T · J`. `torch.autograd.Function` 래핑.
- 추론 경로에 FK 없음 → forward pass 한 번.

### 폐기된 설계
- **f_m / f_s 2단 분리** — 통합으로 불필요.
- **f_s 3안 비교(구 P4)** — 항목 삭제. q 다중해 선택은 네트워크가 학습으로 고정하므로
  NNS의 q 점프 문제(400,000 샘플에도 1.128rad 고정)는 해당 없음.

# III. 전처리 (전 Phase 공통, 확정)

| 항목 | 내용 |
|---|---|
| 원점 | **dorsum** |
| 축 | **손가락 방향 유도** (dorsum 기반 y축은 실측 51mm로 기각됨) |
| 키포인트 | dorsum(원점) / prox(**사슬 50% 중앙**) / distal(손끝) → **K=2** |
| 표현 | keyvector `v_dorsum→distal`, `v_dorsum→prox`. **`v_prox→distal`은 선형종속이라 제외** |
| 스케일 | `L_ref = ‖dorsum − middle_distal‖`, **identity(q=0) 자세 = 최대거리, 상수 고정** |
| joint limit | tanh → `joint_roms` 선형 매핑 |
| 입력 필터 | EMA 등 (지터 원인 제거, 학습 비용 0) |
| 노이즈 aug | 낮은 강도로 포함 (VLA 출력 분포 대비 저비용 보험) |

**dorsum 통일 필요 (P0-1)** — 손마다 위치·parent가 다름:

| | dorsum origin | parent |
|---|---|---|
| human L/R | (0.05, ∓0.01, 0.025) | wrist (미러 ✓) |
| orca L/R | (0,0,0) | 카팔 링크 |
| robotis L | (0.05, −0.01, 0) | base |
| robotis R | (0.00, 0, 0) | base |

→ **robotis 좌우 50mm 어긋남.**

**prox = 사슬 중앙인 이유**: 손가락 관절 수·구조에 무관하게 정의되어 **임베디먼트 확장에 강함.**
센서 실장 위치 기준으로 잡으면 dorsum처럼 손마다 통일 작업이 반복된다.

**L_ref 상수화 이유**: 매 프레임 계산하면 자세에 따라 배율이 흔들려 인위적 스케일 jitter 발생.
- 로봇: `robot_kv_bank` 샘플링 시 `max‖dorsum−middle_distal‖`. ORCA는 `neutral_position`이
  별도 정의돼 있으므로 identity = **q=0**으로 명시.
- 사람: 글러브 시퀀스에서. **strict max vs p99 미결정** (§VII-4).
- 데이터셋 통계(mean/std) 정규화는 쓰지 않는다 → 체크포인트에 통계를 딸려보낼 필요가
  없어지고, 추론 시 통계 불일치로 매핑이 틀어지는 취약점이 사라진다.

# IV. Phase 정의

바뀌는 것은 **F의 내부 구조와 손실뿐.** 전처리·FK·출력 형식은 불변.

## Phase 1 — GeoRT + prox
- F: 손가락별 독립 MLP `(6, 128, 128, n_joints_i)`. 엄지 포함 균질
- 손실: GeoRT 5원칙 (motion preservation / C-space coverage / flatness /
  pinch correspondence / collision-free)
- 학습: **순수 비지도** (사람 분포 + 로봇 분포, 정답 쌍 없음)
- **검증 질문**: prox 추가가 형상 추종을 개선하는가
- **판정**: 형상 오차 43.3° → 20° 이하

> GeoRT의 IK 넷은 손가락당 입력이 지문 3차원뿐이라 중간관절을 볼 수 없고,
> 그것이 측정된 형상 43.3°의 원인. `{side}_sensor_{finger}_proximal`은 URDF 6개 전부에 존재.

## Phase 2 — AnyDexRT 방법론
- F: + **residual affine** (손가락별, A=I / b=0 초기화)
- 손실 교체:

| | 출처 |
|---|---|
| `L_P-Chamfer` | GeoRT Chamfer를 **양방향→단방향** 수정 (로봇 여분 영역 왜곡 회피) |
| `L_dist` | AnyDexRT **신규** — 거리 보존 |
| `L_motion` | GeoRT motion을 **글로벌→로컬 프레임** 수정 |
| `L_align` | AnyDexRT **신규** — few-shot anchor (비지도→약지도 전환의 핵심) |

- 학습: **비지도 3 + 약지도 1**
- **판정**: LMC, \|dq\| p95 (kp 0.072 대비)

**affine을 두는 이유**: few-shot이 잡아야 하는 건 주로 전역 정렬인데, 파라미터 몇 개짜리
아핀에 직접 대응된다. 적은 데이터로 소수 파라미터를 맞추는 편이 MLP 전체를 흔드는 것보다
안정적이고, 학습된 A·b를 들여다볼 수 있어 진단에도 유리.
(GeoRT는 명시 아핀 없이 MLP가 암묵 흡수 / AnyDexRT는 전처리 정규화가 아핀 역할)

## Phase 3 — 셀슈바 백본 + 다중 임베디먼트
- F: **통합 백본 + 로봇별 가벼운 헤드**
  - 토큰 = 키포인트 단위 (5×K), finger-ID 임베딩 주입. K=3 검토
  - **손가락 독립성이 깨짐** — 마스킹 예측은 손가락 간 문맥을 요구
- 학습 2단계:
  1. **백본 사전학습** — 사람 시퀀스만, **로봇 미사용**
     teacher(비마스킹) 각 층 FFN 출력 → IN 평균 → LN = 타겟,
     student(마스킹)가 L2 예측, teacher는 EMA + stop-gradient,
     **motion-aware tube masking** (인접 프레임 정보 누수 방지 + 모션 큰 구간 우선)
  2. Phase 2 손실로 본학습
- **핵심 가치**: 백본은 사람 전용이라 **로봇이 몇 대든 공유**된다.
  ```
  백본 (사람 시퀀스, 로봇 무관) ──┬── 헤드 A (ORCA)
                                  ├── 헤드 B (robotis)
                                  └── 헤드 C (신규 로봇)  ← 소량 앵커로만 학습
  ```
- **필수 실험**: **앵커 개수(5/10/20/50) 대비 LMC 곡선**을 백본 유/무로 비교.
  이게 없으면 "백본 없이 손마다 5~10분 학습하면 되는데 왜?"에 답할 수 없다.
- 가변 관절 수 대응을 위해 헤드도 토큰 기반 설계 필요

### 방법론 선택 근거 (Phase 3)
- **VAE 복원 기각** — rigid FK 데이터에서 복원이 trivial. 복원에 좋은 latent가
  매핑에 좋다는 보장도 없다.
- **저수준 타겟 기각** — raw joint 좌표나 temporal motion을 예측 타겟으로 쓰는 것은
  suboptimal이며 고수준 문맥화 특징이 우수 (Skeleton2vec).
- **HandMIM 교훈** — 타겟을 다운스트림(포즈/회귀) 친화적으로 설계해야 한다.
- **contrastive는 배제하지 않는다** — "회귀 태스크엔 invariance가 해로울 것"이라는
  직관이 실험으로 뒤집힌 사례가 있다. ablation 대상으로 남긴다.

# V. 학습 데이터

| 재료 | 생성 방법 | 용도 |
|---|---|---|
| 사람 분포 | ① 사람 URDF 랜덤 샘플(합성) ② 글러브 실시퀀스 | **합성 사전학습 → 실분포 파인튜닝 2단계** |
| 로봇 분포 | 로봇 URDF 랜덤 샘플 → FK | 도달가능 영역 정의 (Chamfer 대상) |
| anchor 쌍 | 캘리(flat/fist/+splay) + 로봇은 시뮬 자동생성 | `L_align` |

**합성 → 실분포 2단계 이유**: 랜덤 샘플은 `joint_roms` 안에서 균일하지만 실제로는 잘
안 하는 자세가 대부분. 리타게팅이 잘 작동해야 하는 건 실사용 분포(posture synergy)다.
반면 합성은 커버리지 통제가 되고 데이터 수집 전에 개발을 시작할 수 있다.

**자기충돌 필터**: 파일럿에서는 생략. 단 관통 자세가 도달가능 영역에 섞이면 영역이
실제보다 넓게 정의되어 F가 불가능 영역으로 매핑할 여지가 생긴다 → 이상 자세 관찰 시 의심 목록.

## anchor 설계

**캘리 데이터 재활용 (우리 이점)**: 캘리 자세는 로봇 대응이 모호하지 않다
(flat=완전신전, fist=완전굴곡). AnyDexRT가 별도 절차로 수집하던 페어를 이미
워크플로에 있는 데이터로 대체. flat↔fist 보간이 논문의 "굽힘" anchor 유형을 그대로 만든다.

**빈 축 경고**: flat/fist/pinch는 전부 굴곡-신전 축 + 엄지 대립만 커버.
**외전(abduction) 축에 anchor가 없다.** 그런데 미해결 문제가 robotis 외전 흔들림이고
논문 anchor 두 유형 중 하나가 "측면 회전"이다. → **splay 자세 추가 검토** (§VII-1)

**로봇 쪽**: 논문도 사람이 만들지 않는다. 시뮬레이션에서 관절 구성을 균일 샘플링해 자동 생성.

**엄지 예외**: 구조(prox 규약·손실·헤드)는 균질하게 가되, **앵커 수집 절차만 엄지는 예외.**
논문도 엄지 굽힘 앵커는 정확히 정의·수집하기 어려워 로봇 엄지의 사전 생성 궤적에서
샘플링해 조작자가 따라하게 했다.

**핀치 소프트 anchor (P5-2)**: 핀치는 접촉 조건이지 관절 파라미터가 아니라 로봇 대응이
유일하지 않다. → 하드 라벨 대신 유사도 가중:
```
후보군 : 시뮬에서 엄지-검지 접촉 만족 qpos 다수 생성
유사도 : 손가락별 keyvector L2  (확정)
L      = Σ_j softmax(sim_j) · ‖F_kv(x_H) − x_R,j‖
```
- **픽업 단위**: 손가락별 독립은 물리적으로 성립 안 하는 조합을 만든다 → 손 전체(최소 엄지-검지 쌍)
- **온도 τ**: 크면 여러 핀치의 평균 = 핀치가 아닌 자세로 수렴 → 상위 k개(예 5)로 자른 뒤 softmax
- **부트스트랩 순환 차단**: 후보 픽업을 현재 F 예측으로 하면 초기 오염이 굳는다
  → P5-1 수렴 후 warm-up으로 활성화

**핀치 식별을 아키텍처에 넣는 것은 보류**: 논문은 "위치를 못 믿으니 위치와 독립인 분류기"를
택했다. 위치 유사도 기반 식별은 그 반대 방향이므로 글러브 위치 신뢰도 실측이 선행돼야 한다.

# VI. 지표 (P0-2)

## LMC / GMC
둘 다 "조작자가 움직인 방향대로 로봇이 반응하는가"를 재며, **어느 좌표계에서 비교하느냐**가 다르다.

- **GMC (Global)** — 공유 좌표계에서 변위 방향 비교. GeoRT 방식.
  이상적으로 잘 캘리브레이션된 세팅을 가정.
- **LMC (Local)** — 로컬 프레임에서 비교. 캘리브레이션 의존도가 낮고 조작자 제어감과 더 부합.
  **핵심 지표.**

계산: 사람 손끝에 섭동 Δx → 로봇 변위 Δf(x) → 정규화 → 코사인 유사도 → 평균.
LMC는 각 위치의 로컬 프레임 T(x)로 변환 후 비교(로봇 로컬 회전은 최근접 이웃 회전 할당).

논문 실측(7손 평균): 최적화 62.0/52.2, GeoRT 78.3/59.8, AnyDexRT 79.9/**90.2**
→ GMC는 비슷하고 **LMC에서만 격차**. 이것이 미해결 외전 흔들림과 직결.

**구현 시**: LMC 핵심, GMC 병기. **두 값의 격차 자체가 우리 캘리브레이션 품질의 진단 정보.**

## 기타
형상 오차(현 43.3°), 핀치 오차(kp 4.3~8.0mm), **\|dq\| p95** (kp 0.072 / geort 0.225)

# VIII. 미결정

1. **splay 캘리 자세 추가 가능 여부** — 외전 축 anchor의 전제.
   없으면 Phase 2가 굽힘 축만 커버하고 외전 흔들림이 남을 공산이 크다.
2. **캘리브레이션 적용 도메인** — (a)관절각 오프셋/게인 (b)링크길이 스케일 추정
   (c)keypoint 아핀. **(b)면 사용자별로 사람 URDF가 달라져 L_ref 상수 가정이 깨진다.**
3. **핀치 캘리 조합** — 엄지-검지만 vs 엄지-전체. 후자면 핀치 분류기의 상당 부분을
   캘리가 이미 대체.
4. **사람 L_ref** — strict max vs p99 (센서 스파이크 방어)
5. **글러브 rot 신뢰도 실측** — K=3 채택 여부, 핀치 위치 유사도 식별 가능 여부의 근거
6. **손가락별 정규화 vs 손 전체 정규화** — 손가락별은 손가락 간 상대 크기 정보를 지운다.
   Phase 1~2는 손가락별(원안 충실), Phase 3 진입 시 재검토
7. **DexCap 코드 공개 여부** — 공개면 지문 IK와 직접 비교, 아니면 재구현

# IX. 데이터 저장 정책

캘리 데이터는 사용자 손의 기하 특징을 담아 식별 가능성이 있으나,
**캘리 이후 페어는 사용자 편차가 흡수되어 사실상 익명화**된다.

| | 저장 |
|---|---|
| 캘리 후 사람 keypoint ↔ 로봇 qpos 페어 | ○ — 학습에 필요한 건 이것뿐 |
| 캘리 파라미터 (사용자별 보정값) | ✕ — 역산으로 원본 복원 가능, 익명화가 깨짐 |
| 캘리 raw 시퀀스 | ✕ — 파라미터 추출 후 불필요 |

파일명·세션 ID에 이름/사번 미포함. 가명화 + 최소수집을 **처음부터** 적용(소급 정리가 훨씬 비쌈).
법적 판단이 아니므로 저장 스펙 확정 시 사내 개인정보 담당자 확인 권장.

# X. 리스크 — 솔직한 평가

## 1. 구조 완결성
통합 구조는 깔끔하다. 학습 대상이 F 하나, 정확 FK로 GeoRT 한계 하나를 구조적으로 회피.

**남은 구멍: 시간축이 없다.** kp가 \|dq\| 0.072를 낸 건 DLS warm start(이전 해 근처)
덕인데, F는 프레임 독립이라 그 장치가 없다. 남은 건 GeoRT flatness뿐이고, flatness는
"감도 균일"이지 "프레임 간 연속성"이 아니다.

대응 순서: ① 입력 필터(EMA) → ② Lipschitz/평활 페널티 → ③ 그래도 부족하면 시간축.
③으로 갈 경우 **과거 q가 아니라 과거 사람 입력 윈도우**(k=2~3)를 넣는다.
자기 출력 되먹임은 드리프트 위험. GRU 불필요, MLP 입력 차원만 늘리면 됨.

## 2. 성공 가능성

| | 가능성 | 근거 |
|---|---|---|
| Phase 1 (형상 20°) | 중 | prox가 정보를 추가하는 건 맞으나 20°는 임의 목표 |
| Phase 2 (LMC 개선) | **높음** | AnyDexRT 재현. 우리 조건이 원논문보다 유리 |
| Phase 2 (kp \|dq\| 초과) | **낮음** | 시간축 부재 |
| Phase 3 (백본 이득) | 낮~중 | 단일 사용자 데이터로 셀슈바 이득 불확실. 단 다중로봇 확장 가치는 별개 |

가장 가능성 높은 시나리오: **형상·LMC는 kp보다 낫고, \|dq\|는 비슷하거나 약간 나쁨.**

## 3. 논문화
- **기여를 하나로 좁혀야 한다.** "더 나은 글러브 + 촉각 + 다중 로봇"은 시스템 논문/
  점진적 개선으로 읽힌다. 중심은 **"같은 사람 데이터 → N개 로봇"**.
- **필수 실험**: ① 우리 리타게팅 vs DexCap 지문 IK ② 같은 데이터를 N개 로봇으로
  ③ 앵커 개수 대비 품질 곡선
- ①②는 시뮬로 가능, ③도 시뮬 가능. **실물 정책 검증은 로봇팔·마운트가 필요** →
  현 하드웨어로는 ①②③이 현실적 범위이며 그것만으로 한 편은 된다.
- **VLA는 클레임에서 뺀다.** 실제로 돌려 다운스트림 성능을 보이지 않으면
  "붙일 수 있다"에 그치고 리뷰어가 먼저 친다. Future work로만.

## 4. AnyDexRT 수치를 그대로 믿지 않는 이유
- LMC를 저자가 정의하고 GeoRT를 **자체 재구현**해 비교 (원저자 검증 아님)
- 핵심 ablation이 Wuji Hand **한 손에서만** 수행 (R3 일반화 클레임과 논리적 간극)
- Training stability 지표가 자기 방법에 유리하게 설계됐을 가능성 배제 불가
- Pick-10은 오퍼레이터 8명, 오더링 효과 통제 명시 없음

→ **정성적 메커니즘**(local motion이 global보다 캘리브레이션에 강건, anchor가 모호성 해소)은
참고하되, **정량 우위는 우리 하네스로 재현 전까지 설계 결정 근거로 쓰지 않는다.**

## 5. 학습 방식 — 비지도 / 약지도 / 지도
- **지도 ✕** — 사람↔로봇 정답 쌍을 대량으로 만들 방법이 없다. kp로 만들면 성능 상한이
  kp에 묶여 프로젝트 목적 자체가 무너진다.
- **비지도 △** — 해가 유일하지 않아 시드마다 흔들린다(GeoRT: Ability Hand LMC 36.2±11.2
  vs AnyDexRT ±0.1~0.3). 지금 겪는 흔들림과 결이 같다.
- **약지도 ○ 확정** — 캘리 데이터로 앵커를 공짜로 얻는 경로가 이미 있다. 비용 대비 효과 압도적.
- **단 Phase 1은 비지도로 시작.** 앵커 없이 먼저 돌려야 Phase 2에서 앵커 기여를 측정할 수 있다.
