# 리타게팅 v2 계획 (GeoRT 기반 + keyvector)

kp(`solvers/hand/kp_retargeter.py`)는 `feat/kp-hand-retargeter` 에 고정한다. 이 문서는
그 위에 GeoRT 계열 학습 리타게터를 올리는 별도 브랜치의 계획이다.

## 0. 현재 기준선 (같은 하네스, side=right, 실측 핀치 4종 x 20프레임)

| | 형상° | 벌림mm | 핀치접촉 | 펴짐접촉 | \|dq\|p95 | ms |
|---|---|---|---|---|---|---|
| orca kp | 18.3 | 2.0 | 4.3 | 0.7 | 0.074 | 2.4 |
| orca dex | 12.1 | 4.7 | 14.0 | 33.5 | 0.145 | 5.4 |
| robotis kp | 15.8 | 2.3 | 8.0 | 8.9 | 0.072 | 1.9 |
| robotis dex | 16.4 | 6.8 | 27.3 | 27.2 | 0.196 | 6.0 |
| robotis geort | 43.3 | – | 10.5 | – | 0.225 | 2.65 |

v2 는 이 표를 이기지 못하면 채택하지 않는다. 목표 기반 지표로 백엔드를 비교하지 말 것
(과거 두 번 잘못된 결론을 냈다).

## 1. 선행 조건 — URDF (코드에서 보정하지 않는다)

1. **오른손 `*_mcp_abd` 4개 축이 미러가 아니다.** `axis="0 0 1"` 이 좌우 동일한데
   축은 의사벡터라 미러 시 `a' = -M a` 로 부호가 바뀌어야 한다. 실측 미러오차
   15° 에서 index 43.9 / middle 49.6 / ring 43.0 / pinky 35.4 mm, 25° 에서 최대 81mm.
   오른손 4개 축을 반전하면 5·15·25° 전부 **0.00mm**. 엄지 5축과 flex/pip/dip 는 이미 정상.
2. **`sensor_dorsum` 이 손마다 다른 곳에 있다.** keyvector 원점으로 쓰려면 통일이 먼저다.
   - human base_hand: `wrist + (0.05, ±0.01, 0.025)`  (좌우 미러 ✓)
   - orca: 카팔 링크 원점 `(0,0,0)`
   - robotis: **left `(0.05, -0.01, 0)` / right `(0.00, 0, 0)` — 50mm 불일치**
   손목 중앙으로 정의를 확정하고 6개 URDF 전부에 같은 규칙으로 넣는다.
3. 위 두 개가 끝나면 `regenerate.py` 재실행 → `WHATSLAB_MODELS_ROOT` 로 검증.
   동봉 패키지 `dexhand_description` 은 관절명이 구버전(`mcp_z`/`mcp_y`/`thumb_cmc0`)이라
   현재 Visualizer 프로파일과 13/21 이 어긋난다 — 패키지 릴리스 전까지 env 를 반드시 건다.

## 2. 조사 결과 — 실제로 가져올 것

**GeoRT** (facebookresearch, 코드 공개). 손가락별 서브넷 2개: 학습 FK(`n_joint→3`)와
학습 IK(`3→n_joint`, Tanh). 손실 = 방향 + Chamfer + 평탄(2차차분) + 핀치 + 충돌.
**IK 넷 입력이 손가락당 지문 3차원뿐** — 중간관절을 볼 수 없다. 우리 실측 형상 43.3° 의
구조적 원인이 이것이고, 중간관절 추가는 이 구멍을 정확히 메운다.

**AnyDexRT** (arXiv 2607.08341, RSS 2026 워크숍, 코드 미공개). GeoRT 후속.
- MLP `(3,128,128,3)` 손가락별 서브넷 = f_m (사람 지문 → 로봇 지문)
- 손실 = **부분(비대칭) Chamfer** + **거리보존** + **로컬 모션** + 앵커 정렬, 전부 등가중
- **few-shot 앵커**: 자세 유형(측면회전·굽힘)당 5개 → 50~100개로 보간, 시뮬 로봇 자세와 짝
- 접촉분류기 `(6,128,128,1)+Sigmoid`, 접촉 시 사전생성 핀치 템플릿 근방 탐색
- f_s = **NNS** (사전계산 로봇 관절샘플), 293Hz, 하이퍼파라미터 3개
- **Local Motion Consistency 7손 평균 90.2% vs GeoRT 59.8%** ← robotis 외전 흔들림과 같은 문제
- 실기 핀치 성공률 62%

**TopoRetarget** (arXiv 2606.16272, 코드 미공개). 접촉정밀도 7.71mm (DexPilot 14.13,
GeoRT 26.77), 펜스피닝 RL 87.5%, 5ms/프레임. 다만 **물체 메쉬가 필수**다 —
21 키포인트 + 물체 표면 50샘플로 Delaunay 사면체화해서 라플라시안을 맞추는 구조라
물체 없는 텔레옵에는 그대로 못 쓴다. 가져올 수 있는 건 초기화 항
`E_bone = Σ ||(d_k^r - d_l^r) - (d_k^s - d_l^s)||²` (인접 뼈 방향의 **차이**를 맞춤)
하나인데, kp 의 미터스케일 뼈벡터 형상항이 이미 거의 같은 것이다. 신규 가치 낮음.

**Keyvector** = DexPilot 용어(지문→지문 벡터). 우리는 이미 `w(d)`/`f(d)` 스위칭
keyvector 를 측정 기각했다(CHANGELOG). 재도입하지 않는다.

## 3. 제안 아키텍처 평가

제안: 11점(wrist + 5 tip + 5 prox) → keyvector(`v_wrist→X`, `v_tip→prox`) → f_m(손가락별 MLP)
→ f_s(NNS) , 원점 = dorsum(손목 중앙).

### 3.1 맞다고 보는 부분

- **중간관절 5점 추가.** GeoRT 의 구조적 구멍을 직접 메운다. URDF 6개 전부에
  `{side}_sensor_{finger}_proximal` 이 이미 있어 하드웨어가 정의한 점을 쓸 수 있다.
- **손가락별 서브넷 유지.** GeoRT/AnyDexRT 와 같고, 기존 코드 변경이 작다
  (`get_finger_ik` 입력 3 → 6 또는 9).
- **절대좌표 대신 벡터 인코딩.** 팜 원점 추정 오차가 전 채널에 공통으로 들어가는 것을 줄인다.

### 3.2 고쳐야 한다고 보는 부분

**(a) `v_tip→prox` 는 입력으로는 완전히 중복이다.**
`v_tip→prox = v_wrist→prox − v_wrist→tip` 로 정확히 선형종속이다. 네트워크 입력에
넣어도 정보가 0 이고 NNS 차원만 늘린다. **입력은 `v_wrist→{tip,prox}` (30D), `v_tip→prox`
는 손실항으로** 쓰는 게 맞다 — TopoRetarget 도 뼈 방향을 입력이 아니라 에너지에 넣는다.

**(b) f_s = NNS 가 제일 약한 고리다 (실측).**
robotis 오른손, 관절범위 균등 랜덤 사전샘플, 도달 가능한 목표 300개 복원:

| 사전샘플 | 지문당 오차 평균/p95 mm | 1↔2위 이웃 q 점프(중앙) |
|---|---|---|
| 20,000 | 19.2 / 26.2 | 1.155 rad |
| 100,000 | 16.7 / 22.1 | 1.114 rad |
| 400,000 | 14.8 / 19.2 | 1.128 rad |

- 샘플 20배에 오차 4.4mm 개선 — mm 급은 사실상 도달 불가.
- **q 점프가 샘플 밀도와 무관하게 1.1rad 로 고정**된다. 해상도 문제가 아니라 IK 다중해
  문제이므로 샘플을 늘려도 사라지지 않는다. `|dq|p95` 기준선이 kp 0.072 / geort 0.225 인데
  NNS 는 원리적으로 이보다 나쁘다.
- 차원 우려는 **틀렸다**: 15D→45D 로 늘려도 오차가 40.1→35.9mm 로 오히려 좋아졌다
  (추가 좌표가 상관돼 있어 유효차원이 안 늘고 일관성 제약만 더해진다). NNS 의 문제는
  차원이 아니라 불연속이다.

→ **f_s 를 교체 가능하게 만들고 3안을 같은 하네스에서 재라.** (1) NNS, (2) GeoRT 학습 IK,
(3) 우리 kp 의 가중 DLS + IRLS + 시간평활. (3) 은 도달 가능 목표에서 오차 하한이 0 이고
관절한계·연속성을 이미 처리하며 1.9~2.4ms 다. f_m 은 **목표(로봇 keyvector)만** 내고
q 변환은 (3) 에 맡기는 하이브리드가 지금 측정된 모든 우위를 보존한다.

**(c) dorsum 을 유일한 원점으로 삼는 건 위험하다.**
팜 프레임 y축을 dorsum 기반으로 썼을 때 지문오차 51mm 였고, 그래서 지금은 손가락
방향으로 유도한다(dorsum-free). **원점 선택은 축 선택보다 훨씬 덜 취약하므로 dorsum 을
원점으로 쓰는 것 자체는 무리가 없다 — 단 축은 계속 유도된 팜 프레임을 쓴다.** 그리고
1절 2항대로 6개 URDF 의 dorsum 이 통일된 뒤에만 유효하다. 글러브 손목 추정은 체인에서
가장 불확실한 값이고(`wrist` 경로는 실기 검증 이력이 없다) AnyDexRT 의 로컬모션 손실도
절대 앵커 의존을 줄이려고 만든 것이다.

**(d) "사람 키포인트 셀프슈퍼바이즈드 백본" 은 정의가 필요하다.**
GeoRT/AnyDexRT 에서 "self-supervised" 는 *사람-로봇 짝 데이터가 없다*는 뜻이고, 사람
키포인트용 별도 사전학습 인코더는 없다. 별도 백본을 두려면 그 SSL 목적함수가 무엇인지
(재구성? 시간대비? 마스킹?) 정해야 하고, 지금 근거로는 추가 이득이 측정되지 않는다.
**기본안: 별도 백본 없이 f_m 을 매핑 손실만으로 학습**하고, 백본은 이득이 측정된 뒤에 얹는다.

**(e) 최우선 순위는 로컬 모션 손실이다.**
AnyDexRT 의 유일한 큰 격차가 LMC 90.2% vs 59.8% 이고, 그게 정확히 "사람이 굽히는데
로봇 손가락이 좌우로 흔들린다"(robotis)는 미해결 문제다. keyvector 표현 변경보다
이 손실항이 먼저다.

## 4. 단계 계획 — 각 단계에 채택/기각 지표를 붙인다

기존 하네스: `tools/bench_hand_retarget.py` (형상°/벌림mm/접촉mm/|dq|p95/ms).
LMC 는 새로 넣는다: 사람 지문 변위 방향과 로봇 지문 변위 방향의 코사인 > 0 인 프레임 비율.

- **P0. URDF 선행조건** (1절). 미러오차 0.00mm, dorsum 6개 일치. 코드 변경 없음.
- **P1. LMC 지표 추가.** kp / dex / geort 기준선의 LMC 를 먼저 기록. 이게 없으면 이후
  단계의 성패를 판정할 수 없다.
- **P2. GeoRT IK 넷 입력에 중간관절 추가** (3 → 6D: `v_palm→tip`, `v_tip→prox`).
  기존 `get_finger_ik` 한 줄 + 데이터셋 생성만 바뀐다. 채택 조건: 형상 43.3° → 20° 이하.
- **P3. 로컬 모션 손실 + 거리보존 손실 추가** (AnyDexRT). 채택 조건: LMC 가 kp 수준
  이상으로 올라가고 형상·접촉이 P2 대비 악화되지 않음.
- **P4. f_s 3안 비교** (NNS / 학습 IK / kp DLS). 같은 f_m 출력에 대해 3.2(b) 표와 같은
  형식으로 재고, `|dq|p95` 를 동등하게 본다. 여기서 하이브리드 채택 여부가 정해진다.
- **P5. few-shot 앵커** (자세유형당 5개 → 50~100 보간). 글러브+Visualizer 캘리브 흐름을
  재사용한다. 채택 조건: 벌림 지표 개선.
- **P6. 접촉분류기 + 핀치 템플릿.** kp 핀치접촉이 이미 4.3~8.0mm 라 이득 여지가 작다 —
  P1~P5 결과를 보고 착수 여부를 정한다.

각 단계는 실패해도 CHANGELOG 에 기각 근거를 남긴다.

## 5. P7 — 사람 키포인트 backbone (P0~P6 완료 후)

P1~P6 이 끝나기 전에는 착수하지 않는다. 목적은 두 가지고 **서로 긴장 관계**다.

**(1) few-shot 정당화.** 앵커 50~100개가 넓은 이웃을 대신 끌어주려면 latent 가 이미
부드럽게 정렬돼 있어야 한다. 재구성 손실은 이걸 보장하지 않는다 — 그래서
masked reconstruction·뼈길이 불변항은 **뺀다**(두 정당화 어느 쪽도 요구하지 않는다).

```
L_smooth = E_x [ || f_θ(x+δ) - f_θ(x) ||² / ||δ||² ]        (작은 δ, Lipschitz 근사)
L_metric = latent 위의 pairwise 거리보존 (L_dist 를 keyvector 가 아니라 latent 에서)
```

**(2) VLA 내제화 정당화 — "청소된 표현"이 아니라 "분포 안정성".** backbone 이 나중에
VLA 의 distillation target 이 되거나 VLA 출력이 이 latent 에 꽂힌다면, 지금 글러브
센서 노이즈(드롭아웃·EM 간섭)에 강하게 적응시키는 것이 오히려 VLA 의 (노이즈 없는)
키포인트 예측과 분포 괴리를 만든다. 노이즈 강건성은 유지하되 **노이즈 성분이 latent 에
새지 않게** 한다:

```
L_contrastive = InfoNCE(z_clean, z_noisy_same_pose) vs negative(z_다른_pose)
L_backbone    = λ1*L_smooth + λ2*L_contrastive + λ3*L_feasibility(joint_roms)
```

temporal smoothness 는 유지한다(VLA 도 시퀀스 예측이라 공통 요구).

**중복 위험 2건 — 가중치를 낮게 시작한다.**
- `L_metric` 은 keyvector 위의 `L_dist`(AnyDexRT 거리보존, P3)와 겹친다. keyvector 가
  이미 저차원 상대구조라 latent 에 또 얹는 건 중복 정규화일 수 있다.
- `L_smooth` 는 **GeoRT 가 이미 갖고 있는 curvature loss** 와 겹친다. GeoRT 의
  curvature 는 `(f(x+δ) + f(x-δ) - 2f(x))²` 로 2차차분이고 direction loss 는 1차
  방향인데, 둘 다 **신경 FK 를 통과한 출력**에 걸린다. `L_smooth` 는 같은 아이디어를
  latent 에 거는 것이므로, 출력단 항이 이미 있는 상태에서 추가 이득이 있는지부터 잰다.

**ablation (이게 없으면 정당화가 아니라 가설이다).** 같은 gradient step 수로 맞추고
few-shot 앵커 학습까지 끝낸 뒤 LMC(`cos`)를 비교한다:

| | backbone | pretext |
|---|---|---|
| (a) | 매핑손실만으로 end-to-end | 없음 |
| (b) | 동일 | + `L_smooth` |
| (c) | 동일 | + `L_smooth` + `L_contrastive` |
| (d) | 동일 | + 전부 + `L_metric` (중복 확인용) |

(b) 가 (a) 를 못 이기면 backbone pretext 는 기각하고 P6 상태를 최종으로 둔다.
